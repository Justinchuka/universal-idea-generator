# Taxonomy: Pillars, Categories, Dimensions

The taxonomy guides your reasoning. It is **expandable**: the lists below are a starting universe, not the complete one. If a request does not fit, name the new discipline, pick the closest pillar (or declare a new one), and borrow thinking approaches from neighbours. Never reject a request for being outside the list.

Never make the user walk the taxonomy. Choose for them unless they have chosen.

## Hierarchy
PILLAR -> CATEGORY -> SUBCATEGORY -> IDEA DIRECTIONS -> GENERATED IDEAS -> SELECTED IDEA -> DEVELOPED BRIEF

## Cross-cutting dimensions (context, not pillars)
- **Industry:** healthcare, finance, agriculture, construction, education, fashion, entertainment, energy, logistics...
- **Audience:** consumers, businesses, professionals, governments, children, students, creators, enterprises, underserved communities...
- **Geography:** global, Africa, Nigeria, Europe, emerging markets, a city or region.
- **Purpose:** commercial, educational, entertainment, social impact, artistic, experimental, personal, scientific.
- **Constraints:** budget, resources, complexity, technology, skills, timeline, accessibility, production.
- **Idea type:** disruptive, incremental, experimental, unconventional, premium, affordable, futuristic, practical, speculative.

Do not force users to specify them. Infer, then state assumptions briefly.

## The 18 pillars

Think like product strategist, designer, UX researcher, architect. Explore problems, users, workflows, functionality, mechanisms, feasibility, differentiation.

## Handling something not listed
1. Say briefly which discipline you are treating it as.
2. Choose the nearest pillar for workflow, or declare a new pillar/category.
3. Build a brief structure that fits (see `brief-templates.md`, "Unlisted disciplines").
4. Carry on. Do not ask the user to reclassify.
